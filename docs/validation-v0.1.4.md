# v0.1.4 超大内部记录警告优化

验证日期：2026-09-14，macOS / Python 3.9。

目标 Turn：`01a09e8a-35e2-7d92-8c59-dc3781ae08a9`。

升级前对正式服务逐条读取该 Turn 的 38 条请求：全部返回 HTTP 200，也全部重复显示“有单条记录超过 16 MB，已省略”。原因是本轮最初用户消息的关联区间包含大型 compacted 快照；该快照本来就不作为正文显示，却在过滤之前触发了大小警告。

修复使用最多 4 KB 的 JSON 前缀识别外层记录类型。确认属于非正文记录时不再报正文省略；用户/助手消息、工具调用与返回结果，或无法确认类型的记录，仍保留超限提示。没有提高读取上限，没有增加全文聚合加载，也没有修改计费和消息分组。

先添加回归测试，旧版复现大型压缩快照和内部记录误报。修复后的 49 项 Python 测试全部通过，涵盖：跨请求读取本轮用户消息时不重复误报、内部记录过滤、真实超大用户/工具内容仍提示、正文中嵌套的 type 字段不误判、普通压缩记录标识仍保留。前端测试、Python 3.9 语法与编译、JavaScript、shell 语法及 Git diff 检查通过。

正式安装 v0.1.4 后再次逐条读取：38 次 HTTP 200，带警告的请求从 38 条降为 0。每条请求的 context/input/output/tool_results 序列化摘要与升级前完全一致，Turn 用量汇总也完全一致。安装目录、源码和发布 ZIP 的运行文件逐一相同，SHA-256 校验通过。

升级后点击“刷新数据”即可清除前端缓存中的旧警告。若确实有可见内容超过读取上限，仍会明确说明限制针对原始 JSON，可能包含内嵌图片。
