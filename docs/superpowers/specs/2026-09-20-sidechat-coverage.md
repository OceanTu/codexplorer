# 侧边聊天采集补全设计

用户已确认“两路补采”：历史诊断日志恢复＋后续本机遥测。目标是让临时侧聊不再从页面消失，并在有完整计量证据时计算费用。

## 数据与准确性

- 保留 rollout 为已有统计的主要来源。新增只读扫描 logs_*.sqlite，按日志 ID 增量获取用户输入、模型、项目、工具调用和上下文观测值。
- 诊断数据独立保存，不伪造 usage。上下文大小不是计费用量；缺失 Token、缓存或输出分项显示未知。
- 新增 OTLP HTTP JSON 接收端，仅绑定 127.0.0.1，使用安装级随机凭据；白名单保存必要事件字段，舍弃账户、邮箱和无关运行数据。
- 在本机实测支持的事件字段后完成适配。响应 ID 相同的 rollout/遥测只计一次；没有响应 ID 的遥测保留为独立证据，仅在能够排除重复时参与统计。无法可靠去重的记录标记待核验，不猜测。
- 用户正文过滤沿用现有运行时块过滤。历史原始日志轮转后，已经采集的正文摘要和观察数据仍保留。
- 正文最多保留 32 KiB，截断明确提示；不承诺遥测可恢复完整助手答案或工具输出。

## 归属与页面

- 新增紧凑的“补充采集记录”区域，默认折叠，每条点击展开；不新增 Turn 聚合时间线。
- 总览可见未落盘、用量缺失的记录，支持已有时间、模型、项目、关键词筛选。
- 明确父任务的侧聊显示在原 session 中；没有父任务证据的独立展示，可由用户关联到已有 session，不以同项目或时间接近猜归属。
- 本次 OCR 侧聊按用户明确提供的关系关联至“设计数独网格线提取优化”。关联保存在本机数据，不写死进产品。
- 采集状态显示日志补采游标、最近遥测、完整计量/缺失计量条数及待重启状态。未知不能显示为 0 消耗。

## 安装与运行

- 继续 Python 3.9+ 标准库和原生 JavaScript；安装后可删除压缩包、解压目录。
- 增加 telemetry on/off 管理命令和采集页说明。只修改工具管理的配置块，备份原配置；已有 OTel 配置冲突则不覆盖。
- 本机启用仅指向本地接收端，需重启 Codex 才能加载；不自动重启当前正在工作的 Codex。
- 接收端停止时可能丢失临时会话实时事件，页面明确采集覆盖边界；不承诺事后可恢复已丢失用量。

## 验收

先写回归再实现。覆盖诊断输入恢复、同一事件多次扫描、日志重建、缺失字段、真实用户正文过滤、跨来源去重、未知费用、归属、更早/更晚 rollout 到达、HTTP 鉴权与大小限制、配置冲突与卸载清理。
